This is an in-process server stress benchmark. It exercises the actual DHMP client validation/send path and server packet processing through an in-memory direct-IP boundary so NIC, browser and HTTPS speed do not cap the protocol measurement. It is not a raw IPv6 wire-throughput result.

Browser stays out of the hot path

Only one JSON snapshot per second crosses HTTPS. The high-rate records never go to the browser.

Large packets expose throughput

Each packet contains only fixed 16-byte DHMP application records. Larger packets reduce per-packet call overhead and reveal aggregate processing capacity.

Published parity matters

Submitted and published record rates should remain aligned. A gap indicates the path is not processing everything submitted.
