Latest semantics

Each changed pixel becomes one 16-byte application record and is processed through DHMP Latest. No frame reconstruction is required.

Persistent framebuffer

No update means no change. The receiver leaves the previous pixel on screen until a newer update arrives.

What this proves

This page demonstrates DHMP record/state semantics in the deployed backend. Browser control traffic uses ordinary HTTPS POSTs; browsers cannot send raw DHMP IPv6 packets.
